# 架构

## 分层

```
lib/index.js   插件装配：注入 tools/agents/webServer，注册 11 个工具 + 6 条 HTTP 路由，
               管理定时器、状态文件、隔离 worktree 生命周期
lib/watch.js   纯逻辑：什么算新闻、为什么被过滤、能不能唤醒、唤醒文本、水位推进、过滤记录、限流
lib/redact.js  纯逻辑：凭证脱敏
lib/body.js    纯逻辑：请求体解码（含 GBK 兜底，服务端要读中文路径就靠它）
```

`watch.js` / `redact.js` / `body.js` 不 import 任何 `@deepseek-ai/*`，因此可以被 `node --test` 直接测，
不依赖宿主（纯逻辑 + 路由层 + 客户端渲染 + 跨实例重载 + 元数据守门，合计 94 例）。

## 一次轮询

```
每 intervalSec:
  ① 闸门：enabled？退避窗口到点？已有轮次在飞（inFlight）？
  ② gh api repos/<repo>/issues?sort=updated        ← 凭证在插件内部
  ③ 逐条分流（每条都有可读原因，写进 filteredLog，最多留 5 条）：
       带 ack 标签 → 跳过（幂等痕迹在 GitHub 上，换机器也不重报）
       filterReason(item, filters) → 已关闭 / 草稿 / 机器人 / 不在白名单 …
  ④ partitionItems(通过的条目, {seen, lastReported}, cooldown)
       → fresh（真有新闻） / absorbed（我们自己的写操作，静默吸收）
  ⑤ fresh 为空 → 清掉过期的 lastDeferred，结束（零模型调用）
  ⑥ 仅观察模式？→ 只记「本会唤醒哪几条」，写 history(reason=observe)，不唤醒
  ⑦ 活跃时段外？→ 攒着（水位不动）
  ⑧ 每小时上限到了？→ 只记 lastDeferred（水位不动，下轮还能认成 fresh）
  ⑨ 会话不在 / 不 idle？→ 记错误或 lastDeferred（忙时绝不建隔离区）
  ⑩ 隔离模式？→ 开 worktree，把路径写进消息
  ⑪ Agent.followup(消息) —— 消息含条目列表、隔离路径、本条目主理目标、完成标准
       成功 → advanceSeen + recordReported + cursor 前移
       失败 → 水位不动，bumpFailure（指数退避，封顶 30 分钟）
```

## 为什么是 followup 而不是 inbox.append

`Inbox.append` 只把消息排进队列，空闲会话不会自己消费，客户端把它显示成“待发送草稿”。
`Agent.followup()` 会**启动驱动**，消息成为一条真正的用户轮次。

## 为什么只在 idle 时注入

在一轮进行中注入，消息会落进客户端的 pending-input 区；客户端下次同步可能把已发送输入当成草稿回填并重发。
等待 idle 最多多花一个轮询周期。

## 状态文件

`~/.dsh/state/session-superagent/watchers.json`

```json
{ "watchers": { "<repo>#<sessionId>": {
    "repo": "o/r", "sessionId": "session-…", "intervalSec": 60,
    "enabled": true, "observe": false, "isolated": false, "workdir": "E:/repo",
    "filters": { "labels": ["ai-fix"], "ignoreLabels": [], "skipClosed": true,
                 "skipBots": true, "skipDrafts": true, "onlyAssigned": false, "assignee": null },
    "batchLimit": 5, "maxWakesPerHour": 6, "activeHours": null, "goal": "",
    "cursor": "2026-11-01T09:41:15Z",
    "seen": { "2": "2026-11-01T09:41:15Z" },
    "lastReported": { "2": "2026-11-01T09:41:15Z" },
    "lastPoll": "…", "lastWake": "…", "lastError": null,
    "filteredLog": [ { "number": 7, "title": "…", "reason": "机器人" } ],
    "history": [ { "at": "…", "numbers": [12], "ok": true, "reason": null } ] } } }
```

**落盘规则**：轮询结果字段（`lastPoll`/`seen`/`cursor`/`filteredLog`/`history`/…）由 `mergePollResult()`
按白名单写回；配置类字段（`enabled`/`filters`/`intervalSec`/…）**只以盘上为准**，
否则 tick 收尾会把「暂停」写回成运行中。
